## 1. 结论

项目中已经存在针对 **国家 CMA 官方站 `https://cma.cnca.cn/cma`** 的离线查询与场所能力抓取脚本，并有真实 JSON 与 SQLite 产物。

此前 Web 服务曾误把另一套“CMA 实验室公共查询源”当作国家 CMA；这条错误接线已经隔离。当前国家 CMA 的线上搜索、同步和徽章处于暂停状态，等待把已有的**场所级离线数据链路**以可靠方式导入主库。

## 2. 两类 CMA 数据必须隔离

| 名称 | 来源 | 用途 | 规则 |
| --- | --- | --- | --- |
| CMA 实验室 | 项目现有 CMA 实验室公共查询来源 | 实验室/资质查询 | 保持既有功能 |
| 国家 CMA | `cma.cnca.cn` | 获证机构、分场所、能力范围 | 仅能使用该来源或其审核后的离线数据 |

**禁止：**

- 不要用 `CmaScraper` 或 CMA 实验室数据填充国家 CMA 表。
- 不要把一个分场所的能力说成整个机构所有场所均具备。
- 不要将 CMA 实验室与国家 CMA 的徽章、文案、数据库或订阅混用。

## 3. 真实脚本

### 3.1 `scripts/cma_fetch_place.py`

这是当前最有价值的历史脚本，职责为“证书号 → 分场所 → 场所能力明细”。

| 项目 | 内容 |
| --- | --- |
| 官方站根地址 | `https://cma.cnca.cn/cma` |
| 机构检索 | `/solr/tBzAbilitySearch/list` |
| 场所/能力详情 | `/solr/tBzAbilitySearch/formAbility` |
| 本地数据库 | `data/cma_national.db` |
| 场所表 | `cma_places` |
| 能力表 | `cma_abilities` |

概念流程：

1. 访问公开查询页建立会话。
2. 以 CMA 证书号查询机构关联信息。
3. 读取该证书下的分场所列表。
4. 在满足网站验证要求的合法会话中，按场所分页读取能力数据。
5. 写入 SQLite 或输出 JSON。

> 站点对查询设置了验证。历史代码里包含自动处理实现，但不要把它作为 NAS/Web 服务的默认能力，也不要继续扩展自动绕过方案。生产接入应使用官方授权接口、人工触发的合法会话或审核后的离线导入。

### 3.2 `scripts/cma_search.py`

这是历史搜索脚本，当前**不适合直接作为线上提供者**：

- 包含两次 `search_certificate` 定义；后定义覆盖前定义。
- 包含两次 `main` 定义；后定义覆盖前定义。
- 前半部分是 requests/API 风格，后半部分是 Playwright 浏览器风格；当前 CLI 实际走后者。
- 有部分历史中文文本显示异常，维护成本高。

后续应拆成独立工具：一个人工辅助查询工具、一个离线结果解析/导入工具。不要继续在同一文件叠加逻辑。

## 5. 离线数据模型

### 5.1 `cma_places`

| 字段 | 含义 |
| --- | --- |
| `place_id` | 国家 CMA 分场所 ID，主键，必须保留 |
| `cert_code` | CMA 证书号；一个证书可对应多个场所 |
| `org_name` | 机构名称；历史脚本可能未完整填入，待修复 |
| `place_type` | 场所类型 |
| `place_name` | 场所名称 |
| `place_address` | 场所地址 |
| `apply_id` | 与读取能力关联的申请/机构 ID |
| `synced_at` | 抓取或写入时间 |

### 5.2 `cma_abilities`

| 字段 | 含义 |
| --- | --- |
| `place_id` | 所属分场所 ID |
| `cert_code` | CMA 证书号 |
| `category` | 大类 |
| `type_name` | 类别 |
| `item_name` | 产品/项目/参数 |
| `std_name` | 标准名称 |
| `std_code` | 标准编号 |
| `synced_at` | 写入时间 |

### 5.3 建模规则

- 匹配结果必须至少关联 `place_id`；界面应展示匹配场所。
- 现有表没有可靠的上游能力唯一 ID，也没有保留所有可能的限值/范围字段；导入正式主库前需评估扩展。
- 标准匹配先规范化标准号，再区分同号同年、跨年可引用、无匹配等状态。

## 6. 已确认的分页重复问题

### 6.1 实测现象

对 `cma_节能材料_测试.json` 与 `data/cma_national.db` 复核结果：

```text
JSON 声明总数: 420
JSON 数组行数: 420
SQLite 行数: 420
JSON 与 SQLite 五字段映射: 完全一致
按五字段组合统计: 61 个重复组
其中固定偏移 30 行的重复: 60 对
```

样本中第 121～180 条与相差 30 的位置高度重复，偏移量正好符合历史分页大小 `30`。

### 6.2 已定位根因

`cma_fetch_place.py` 在遇到“参数有误”或“服务器无法解析”时，会回退 `page_no` 后重试。这会重新抓取已经成功的上一页，并把结果再次追加。

```text
当前错误路径：失败页 → 页码减 1 → 上一页再次请求 → 已成功结果再次 append
```

因此，历史 `420` 是抓取行数，不应直接当作可信的唯一能力数。

### 6.3 后续修复要求

1. 失败页只能重试当前页，不得回退到成功页。
2. 成功处理完成后再推进页码。
3. 保留每页的原始结果、页码、累计唯一数与错误原因。
4. 有最大重试次数、连续空页保护和完整结束条件。
5. 完成后输出：源站总数、原始行数、唯一行数、重复行数、实际页数。
6. 先保留尽量完整的源字段，再做去重；当前五字段相同不一定代表源站业务项完全相同。

## 7. 当前 Web 服务状态

相关代码：

```text
src/services/nat-cma-service.ts
src/api/nat-cma-routes.ts
public/js/app-qual-lab.js
```

目前 `NatCmaService` 默认使用 `NationalCmaProviderUnavailable`，错误 CMA 实验室来源不会再参与国家 CMA 搜索、同步、徽章或计数。

这表示：**线上服务尚未正确接入真实的场所级数据**，不表示项目没有国家 CMA 抓取链路。

旧服务模型曾按“机构证书级”覆盖能力；真实数据必须改为：

```text
证书号
  └─ 场所（place_id）
       └─ 能力项
```

同证书的多个场所不得复制彼此的能力。

## 8. 推荐接入路线

### 阶段 A：离线数据质量

- 修复分页重试、去重、断点和 `org_name` 解析。
- 为一次抓取保存证书、场所、开始/结束时间、页数、源站总数、唯一数、失败原因。
- 维持离线库或规范 JSON；不要让 NAS 容器默认定时访问该站。

### 阶段 B：导入主库

- 新建 TypeScript 导入器，将审核后的 SQLite/JSON 导入主库的 `nat_cma_*` 表。
- 以 `place_id + source_id` 为理想唯一键；无官方行 ID 时保存稳定哈希及原始记录。
- 按**场所**进行事务化原子替换；导入失败不能破坏旧数据。
- 为标准号建立规范化索引。

### 阶段 C：恢复前端

- 设置页显示数据更新时间、场所数、能力数、导入来源和失败原因。
- 标准检索、LABR、文件库的国家 CMA 徽章必须显示匹配场所和匹配等级。
- 订阅对象应是场所，而不是只订阅证书号。
- 数据过期或缺失时不要显示绿色匹配徽章。

### 阶段 D：后续自动化

仅在获得官方授权接口、导出能力或明确许可后评估周期更新。任何同步都应限频、排队、可暂停、可追溯，并输出任务状态。
