# StdHub 全站 UI 重构规范

## 1. 项目目标

将 StdHub 从多个独立工具页面组成的深色界面，统一为面向标准检测、质量与合规人员的专业操作工作台。重构只改变视觉层级、交互组织和响应式表现，不改变既有业务语义。

必须保留：

- 页面入口、主要导航名称和现有功能边界
- 表单字段名称、顺序、控件 ID 和脚本调用关系
- 搜索、下载、预览、文件管理、资质查询、同步和诊断流程
- 权限、主题、任务状态和 API 数据契约
- 已完成的分页图片 PDF 阅读器及其性能行为

## 2. Design Read

这是面向标准检测、质量与合规人员的全站工作台重构。设计语言应克制、工业化、文档优先，强调可信度、可扫描性和长时间使用舒适度。

设计参数：

| 参数 | 值 | 含义 |
|---|---:|---|
| DESIGN_VARIANCE | 4 | 结构稳定，允许适度非对称和上下文布局 |
| MOTION_INTENSITY | 3 | 以即时反馈为主，不使用装饰性自动动画 |
| VISUAL_DENSITY | 7 | 支持高频专业工作，同时保持清晰分组 |

## 3. 设计语言

### 3.1 色彩与主题优先级

- Paper 是现代设备的主要工作主题，使用低眩光纸张底色、深灰文字和克制的暖色交互强调。
- 经典主题服务于老版本电脑和 Chrome 109，必须提供纯十六进制或 rgba 回退，不依赖 color-mix、OKLCH、模糊或复杂合成效果。
- 深色主题采用炭黑和冷灰表面，钴蓝作为唯一交互强调色。
- 绿色、橙色、红色只用于真实成功、警告和错误状态。
- 移除紫色外发光、背景网格和无业务含义的渐变。
- 浅色主题使用冷白和浅灰，不引入另一套强调色。
- 四个主题映射同一套语义变量，不允许页面单独硬编码只适用于深色的颜色。
- 每个阶段的视觉验收顺序为 Paper、经典、深色、浅色。

### 3.2 排版

- 中文正文使用清晰的系统中文无衬线回退栈，避免加载外部字体造成离线和内网问题。
- 标准号、时间、统计数字和日志字段使用统一等宽字体栈。
- 页面标题、区段标题、标签、正文和辅助文字形成固定五级层级。
- 禁止把占位文字当作字段标签。

### 3.3 形状与层级

- 输入和按钮采用 8px 圆角。
- 结构容器采用 10px 或 12px 圆角。
- 标签可以使用全圆角，但仅表示紧凑状态或筛选条件。
- 普通页面结构依靠间距、背景层和稀疏分隔线，不依靠卡片套卡片。
- 阴影只用于抽屉、菜单、弹窗和其他真实浮层。

### 3.4 图标

- 全站使用一套来自成熟图标库的线性图标，统一描边和尺寸。
- 通过本地 SVG sprite 提供，保证离线部署和原生前端兼容。
- Emoji 不再承担导航、主题、账户或业务操作图标。
- 图标按钮必须提供可访问名称和悬停提示。

## 4. 公共组件契约

### AppShell

- 桌面侧栏固定宽度约 216px，顶栏约 56px。
- 环境提示位于顶栏之后、页面标题之前，不与标题覆盖。
- 内容区最大宽度约 1480px，数据密集页面可以使用完整可用宽度。
- 移动端使用底部四入口导航，内容高度采用动态视口单位并考虑安全区。

### PageHeader

- 左侧包含标题和一句用途说明。
- 右侧最多保留一个主要操作，其他操作进入更多菜单。
- 页面状态、数据时间和作用范围使用独立状态区，不与按钮混排。

### SearchWorkbench

- 搜索输入和提交操作保持最高视觉优先级。
- 来源、范围和高级条件为第二层控制。
- 最近搜索、示例和模板只在空状态中出现。
- 标准搜索、Labr 和资质搜索复用布局，不强行复用领域结果模板。

### DataTable

- 表头、排序、选择、分页、加载和空状态统一。
- 选择型操作只有在选中行后才出现。
- 行主要操作直接可见，危险操作进入上下文菜单。
- 移动端明确转换成字段优先的卡片行，不进行横向压缩。

### EmptyState

- 区分未开始、无匹配、暂无数据、加载失败和权限不足。
- 提供当前场景下唯一合理的下一步。
- 不使用占据大半屏幕的装饰插画。

### Drawer 与 Dialog

- 统一遮罩、层级、标题区、操作区和关闭方式。
- 支持 Escape、焦点限制、焦点恢复和键盘可见轮廓。
- 移动端抽屉根据任务转换成全屏页或底部面板。

## 5. 页面蓝图

### 标准检索与 Labr

- 使用紧凑搜索工作台，搜索框为页面主焦点。
- 来源控件视觉降级，但保留选择逻辑和顺序。
- 结果行优先显示标准号、名称、状态、来源、资质信息和主要操作。
- 预览为主要查看行为，下载及其他动作保持清晰但不过度强调。
- 批量操作在产生选择后出现。

### 工具箱

- 查新：输入和说明在主工作区，实时校验和结果紧邻操作。
- 批量下载：左侧输入和解析，右侧为来源匹配与下载队列。
- 标准补全：按“选择文件、配置字段、执行处理、下载结果”组织。
- 三种工具共享模式切换、字段结构、反馈和错误样式。

### 本地文件库

- 保持表格优先的信息架构。
- 搜索、筛选、统计和普通浏览操作处于稳定工具栏。
- 移动、删除等批量操作只在选择后出现。
- 预览入口更明确，文件来源、更新时间和状态更易扫描。

### 下载历史

- 按日期分组显示活动，支持来源、状态和文本筛选。
- 每条记录提供打开、重试或定位到文件的上下文操作。
- 清空历史进入更多菜单并经过确认。

### 资质查询

- 普通、详细、批量查询采用稳定的模式切换。
- 普通查询以机构和标准结果为主。
- 详细查询将高级条件放入可持续编辑的筛选区域。
- 批量查询同时显示输入解析摘要和分组结果。

### CMA 一单一库

- 顶部状态条明确当前范围、数据时间、同步状态和异常数量。
- 同步作为唯一主操作，导出、诊断和黑名单进入更多菜单。
- 能力项目库、机构比对和领域订阅保持稳定子导航。
- 结果优先呈现缺失、冲突、过期等需要处理的异常。

### 运行日志

- 使用高密度运维控制台结构。
- 顶部为紧凑运行摘要，中部为统一查询、时间、级别和来源筛选。
- 主体为事件流，详细载荷按需展开。
- 状态颜色只表达真实级别，不给每行添加装饰状态点。

### 使用统计

- 时间范围整合进页面标题区域。
- KPI 使用普通数字摘要，不使用三张等权卡片。
- 趋势为主视图，来源表现和健康异常为次级视图。
- 总量为零时显示无数据，不计算或展示 100% 成功率。

### 系统设置

- 桌面使用左侧分区导航和右侧设置内容。
- 移动端使用分区列表进入单独设置视图。
- 下载、文件库、订阅、同步、诊断和关于保持原顺序。
- 设置行统一标签、说明、控件、即时状态和保存反馈。
- 重置与危险操作独立隔离。

### 我的

- 保留账户摘要和四入口移动导航。
- 显示真实提醒、角色相关快捷入口和显示偏好。
- 移除 Emoji，避免重复桌面侧栏中的低价值入口。

### PDF 阅读器

- 保持当前单工具栏、分页图片、延迟加载和移动操作面板。
- 全站颜色、图标和浮层更新时同步映射视觉变量。
- 不改变缓存、预加载、回收、缩放、全屏和原文件行为。

## 6. 动效规范

- MOTION_INTENSITY 为 3，普通悬停、按压、菜单和抽屉优先使用 CSS。
- 动画必须表达层级、反馈或状态变化，不添加装饰性循环动画。
- 如需 GSAP，只用于可中断的工作区切换或连续任务状态编排。
- 仅动画 transform 和 autoAlpha，使用时间线而不是手工 delay 链。
- 必须通过 matchMedia 支持 prefers-reduced-motion，并在页面切换时清理。
- 不使用 ScrollTrigger、滚动劫持、视差或常驻动画。

## 7. 响应式与无障碍

- 统一使用 700px、1024px、1440px 三个主要布局阈值，与 PDF 阅读器移动边界对齐。
- 所有多栏页面明确提供单栏或主从视图降级。
- 触摸目标至少 44px，正文和交互文本满足 WCAG AA 对比度。
- 所有功能支持键盘访问，焦点样式不依赖颜色变化。
- 加载骨架与最终结构匹配，避免布局跳动。

## 8. 实施批次与验收

### 批次 A：基础与外壳

交付设计变量、图标 sprite、全局组件、桌面壳、移动导航、任务中心基础样式。验收全部页面仍可进入，主题正常，脚本无错误。

### 批次 B：核心检索

交付标准检索、Labr、资质查询和 CMA 一单一库。验收原有请求参数、结果动作、批量选择和查询模式不变。

### 批次 C：文件与工具

交付本地文件库、下载历史和工具箱。验收预览、下载、移动、删除、上传、导出和任务反馈不变。

### 批次 D：观察与配置

交付日志、统计、设置和我的。验收统计口径、日志筛选、设置保存、诊断、主题和权限不变。

### 批次 E：全局状态与质量

完成抽屉、弹窗、详情、空状态、错误状态、动效、无障碍、性能和全站视觉回归。

每批次完成条件：

1. 更新 `task_plan.md` 阶段状态。
2. 将实际修改和测试结果写入 `progress.md`。
3. 将新的约束或技术发现写入 `findings.md`。
4. 通过 JavaScript 语法、CSS 入口、TypeScript 构建和相关自动化测试。
5. 完成桌面和移动端代表性页面浏览器检查。

## 9. 跨电脑继续开发

在新电脑开始工作时按以下顺序恢复：

1. 拉取仓库并安装锁定依赖。
2. 阅读 `task_plan.md` 获取当前阶段和未完成项。
3. 阅读 `progress.md` 获取最近修改和测试结果。
4. 阅读 `findings.md` 获取架构限制和已知问题。
5. 阅读本文件获取长期设计标准。
6. 检查工作树和最近提交，不重复已经完成的阶段。
7. 从当前阶段第一个未勾选项目继续，完成后立即更新记录。

完整的环境准备、skills 安装命令和恢复检查见 `docs/AI_DEVELOPMENT_SETUP.md`。

## 10. 禁止事项

- 不进行 React、Vue 或其他框架迁移。
- 不将营销站视觉模式套在数据工作台上。
- 不重新引入紫色光晕、背景装饰网格或 Emoji 导航。
- 不为了使用 GSAP 而制造动画。
- 不批量重命名业务 ID、路由、标签或接口字段。
- 不在未运行对应回归测试时跨多个业务批次修改交互逻辑。
